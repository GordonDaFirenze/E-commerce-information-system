## 2. Назначение и цели создания ИС

### 2.1 Назначение системы
**Вид автоматизируемой деятельности:** учётно-торговая деятельность интернет-магазина (обработка информации о товарах и заказах).

Система предназначена для автоматизации процессов:
* ведения каталога товаров;
* оформления и учёта заказов;
* просмотра статуса заказов (для «покупателя»);
* управления товарами и заказами (для «администратора»).

**Область применения:** малый бизнес (например, продажа электроники, одежды или книг) или учебные цели.

**Конечные пользователи:**
* покупатель (неавторизованный/авторизованный);
* администратор.

### 2.2 Цели создания системы
* Снижение времени на обработку заказов (не менее чем на 30% в сравнении с ручным учётом).
* Исключение ошибок при учёте остатков товаров.
* Доступ к информации об остатках покупателю в реальном времени.
* Автоматический поиск вместо ручного просмотра.

**Критерии оценки достижения целей:**
* система считается успешно реализованной, если она позволяет администратору добавлять/изменять товары, а покупателю — оформлять заказ без сбоев;
* функциональные тесты демонстрируют выполнение всех заявленных операций.

## 3. Характеристика объекта автоматизации

### 3.1 Краткие сведения
Объект автоматизации — деятельность сотрудников и владельца малого интернет-магазина. В настоящее время учёт ведётся с использованием:
* бумажных журналов и/или таблиц Excel;
* ручного приёма заказов по телефону или через сообщения в мессенджерах.

**Основные недостатки существующей организации работы:**
* отсутствие единого каталога товаров с актуальными остатками;
* задержки в обработке заказов из-за необходимости сверки с бумажными записями;
* невозможность для покупателя самостоятельно проверить наличие и стоимость;
* частые ошибки при повторном вводе данных заказа.

**Краткая характеристика объекта автоматизации (типовой рабочий день):**
* количество товарных позиций — до 100;
* количество заказов в день — до 10–15;
* персонал: 1 администратор (он же менеджер), покупатели — внешние пользователи.

## 4. Требования к ИС

### 4.1 Требования к системе в целом

#### 4.1.1 Требования к структуре и функционированию системы
Система реализуется как консольное приложение на языке C++ (стандарт C++17).

**Архитектура:**
* подсистема управления товарами (администрирование);
* подсистема оформления заказов (покупатель);
* подсистема хранения данных (файлы CSV или SQLite).

* **Количество уровней иерархии:** 2 (пользовательский интерфейс — бизнес-логика — хранение).
* **Связи между компонентами:** через вызовы функций, данные передаются через объекты классов.
* **Способы связи для информационного обмена:** внутри системы — программные интерфейсы; со смежными системами — не предусмотрено.

**Режимы функционирования системы:**
* интерактивный (диалог с пользователем через меню);
* пакетный (не предусмотрен).

**Диагностирование:** при запуске проверяется наличие файлов данных, при ошибках ввода выводятся сообщения. Перспективы развития — в будущем возможен переход на графический интерфейс и многопользовательский режим.

#### 4.1.2 Требования к численности и квалификации персонала системы
* **Численность персонала:** 1 администратор (он же оператор). Покупатели не требуют учётных записей.
* **Квалификация:** администратор должен уметь запускать программу, различать меню для администратора и покупателя, вводить данные с клавиатуры. Специального обучения не требуется.
* **Режим работы персонала:** по мере необходимости, в любое время работы магазина.

#### 4.1.3 Требования к надёжности системы
**Состав показателей надёжности:**
* время безотказной работы (при отсутствии внешних сбоев) — не менее 4 часов непрерывно;
* вероятность сохранности данных при корректном завершении — 100%;
* при аварийном завершении (выключение питания) — последние изменения могут быть потеряны, но структура файлов не разрушается.

**Аварийные ситуации:**
* внезапное выключение компьютера;
* повреждение файла данных (например, ручное редактирование).

**Требования к надёжности ПО:** программа не должна «падать» при неверном вводе — все ошибки обрабатываются без аварийного завершения.

### 4.2 Требования к функциям (задачам), выполняемым системой

**Подсистема «Покупатель»:**
* просмотр каталога товаров (название, цена, остаток);
* поиск товара по названию (частичное совпадение);
* добавление товара в корзину (с указанием количества);
* просмотр содержимого корзины;
* оформление заказа (ввод ФИО, номера телефона, адреса доставки);
* просмотр статуса своих заказов (по номеру заказа или ФИО).

**Подсистема «Администратор»:**
* авторизация (условная — выбор роли в меню);
* добавление нового товара (название, цена, количество);
* редактирование данных о товаре;
* удаление товара (или пометка как «снят с продажи»);
* просмотр всех заказов (`id`, дата, статус, сумма, контакты);
* изменение статуса заказа (`новый` → `в обработке` → `отправлен` → `доставлен`);
* формирование отчёта: общая сумма продаж за период (вывод на экран).

### 4.3 Требования к видам обеспечения

#### 4.3.1 Требования к информационному обеспечению
**Состав и структура данных:**
* товары (`ID`, название, цена (`float`), количество (`int`));
* заказы (`ID_заказа`, дата (строка `YYYY-MM-DD`), статус (строка), сумма (`float`), ФИО, телефон, адрес);
* состав заказа (`ID_заказа`, `ID_товара`, количество).

* **Способы организации данных:** текстовые файлы в формате CSV (разделитель `;`). В перспективе — SQLite.
* **Информационный обмен:** все компоненты программы работают с одним набором файлов.
* **Классификаторы:** не используются.
* **СУБД:** не требуется (используются собственные средства чтения/записи).
* **Защита данных от разрушений:** резервное копирование перед записью (файл `.bak`).

**Контроль, хранение, обновление и восстановление:**
* при запуске программа проверяет наличие файлов, если их нет — создаёт пустые с заголовками;
* восстановление из резервной копии — вручную.

#### 4.3.2 Требования к лингвистическому обеспечению
* Язык интерфейса — русский.
* Язык программирования — C++ (комментарии допускаются на русском или английском по выбору разработчика).
* Формат входных/выходных данных — строки в кодировке UTF-8.

#### 4.3.3 Требования к программному обеспечению
* **Покупные программные средства:** не используются.
* **Независимость от СВТ:** программа должна работать на любом ПК с ОС Windows (10/11) без установки дополнительных библиотек (кроме стандартных).
* **Качество ПО:** обработка всех исключений, отсутствие утечек памяти, понятная структура классов.

#### 4.3.4 Требования к техническому обеспечению
* **Процессор:** x86_64, 2 ГГц или выше.
* **ОЗУ:** не менее 4 ГБ.
* **Свободное место на диске:** не менее 100 МБ.
* **Периферия:** клавиатура и монитор с текстовым режимом.
